# A 담당 기능 보완 및 검증 기록

## 범위

서버 실행·소켓 연결, 로그인·접속 관리, 클라이언트 통신·사용자 목록을 보완했다. 공백 구분 명령어와 `ClientHandler`에서 담당 메서드 한 줄을 호출하는 규칙을 유지했다. B·C 기능 자체는 구현하지 않았다.

## 원인 분석과 수정

| 우선순위 | 원인과 발생 경로 | 수정 |
|---|---|---|
| 1 | 사용자 관리 잠금 상태에서 `send`가 소켓 쓰기를 기다림. 수신하지 않는 연결 때문에 다른 로그인·목록 처리도 대기 | 연결별 128개 전송 큐와 전송 작업을 사용. 사용자 잠금 안에서는 큐에 등록만 하고 전송 순서를 유지 |
| 2 | 8192자 초과 입력에서 발생하는 `IllegalArgumentException`을 콘솔 입력 스레드가 처리하지 않음 | 해당 입력의 오류를 안내하고 다음 줄 처리. 통신 실패는 연결 종료 경로로 전달 |
| 3 | 로그인하지 않은 연결의 대기 시간 제한이 없어 50개 자리를 계속 점유 가능 | 접속 시각 기준 30초 로그인 마감. 부분 입력으로 마감 연장 불가 |
| 4 | 연결 정리 메서드의 실행 예외가 이후 사용자·서버 정리를 건너뛰게 함 | 단계별 예외 격리, 최종 연결 목록 제거, 서버 작업 풀 종료 보장 |

전송 한 건과 로그아웃 응답 마무리는 5초로 제한하고 100밀리초 간격으로 검사한다. 로그아웃은 앞선 응답과 `/LOGOUT_OK`를 보낸 다음 연결을 닫는다. 전송 큐가 가득 차거나 전송 시간이 초과하면 해당 연결을 종료한다. 수신·전송 작업 풀도 각각 최대 50개 스레드와 50개 대기 작업으로 제한한다.

서버와 클라이언트는 운영체제에 상관없이 LF를 보내도록 맞췄다. CRLF 수신은 계속 지원한다. 변경된 코드의 주석은 한글로 작성하고 데몬 스레드 설명도 바로잡았다.

## 검증 방법

```sh
# 컴파일과 포트 없는 테스트
./run.sh test-local

# 위 테스트 후 실제 TCP 통합 테스트까지 수행
./run.sh test
```

Windows에서는 각각 `.\run.ps1 -Mode test-local`, `.\run.ps1 -Mode test`를 사용한다. PowerShell 실행 자체는 이 환경에서 검증하지 않았다.

| 검사 | 결과 | 근거와 범위 |
|---|---|---|
| Java 17 대상 컴파일 | 통과 | main·test 소스 전체 컴파일 |
| 문자열 처리 | 통과 | StarterTest codec: 공백 보존, CRLF, 불완전한 메시지, 길이 제한, 잘못된 인자, 개행 주입 |
| 콘솔 입력 복구 | 통과 | ConsoleInputTest: 긴 입력 뒤 목록·종료 명령어 처리, 오류 안내, 통신 예외 전달 |
| 로그인·목록·재접속 | 통과, 소켓 대역 | ReliabilityTest: 로그인 전 거부, 중복·재로그인 거부, 발신자 검사, 목록 알림, 로그아웃 응답 순서, 재접속·강제 연결 해제 |
| 동시성 | 통과, 소켓 대역 | 8개 연결이 같은 ID로 동시에 로그인하여 정확히 한 연결만 성공, 동시에 종료 후 사용자 목록 비움 |
| 연결·입력 제한 | 통과, 소켓 대역 | 50개 접속 후 초과 연결 거부, 긴 프레임 연결 해제 후 새 사용자 정상 처리 |
| 로그인 마감 | 통과, 소켓 대역 | 무입력·불완전한 입력 연결 종료, 로그인한 연결은 유지. 테스트에서는 300밀리초로 단축 |
| 느린 전송 | 통과, 소켓 대역 | 한 연결의 쓰기를 의도적으로 막아도 다른 연결의 로그인·목록 조회 성공, 시간 초과 연결 제거 |
| 전송 큐 상한 | 통과, 소켓 대역 | 전송을 막은 상태에서 큐를 채우면 시간 초과 전에도 해당 연결 정리 |
| 종료 중 예외 | 통과, 소켓 대역 | 방 정리에 실행 예외를 주입해도 모든 사용자 제거 및 서버 작업 스레드 종료 |
| 실제 TCP 통합 | 미검증 | 수정 전·후 모두 ServerSocket 바인딩에서 `Operation not permitted` 발생 |

ReliabilityTest는 포트를 열지 않는 소켓 대역을 주입하되 실제 ChatServer의 accept 루프, ClientHandler, UserManager와 작업 풀을 실행한다. 읽기·쓰기 대기와 연결 해제를 메모리로 재현한다. 운영체제 TCP 버퍼, 실제 단절·지연, LAN 통신을 검증한 것으로 해석하지 않는다.

소켓 대역 신뢰성 검사는 최초 통과 후 동시성 재현을 위해 3회 추가 실행했으며 모두 종료 코드 0으로 통과했다. `bash -n run.sh` 구문 검사도 통과했다.

긴 프레임 검사와 방 정리 예외 주입에서는 의도적인 오류 로그가 출력된다. 마지막 PASS와 종료 코드 0으로 검사 성공을 판단한다.

## 남은 확인

- 포트를 열 수 있는 일반 터미널에서 `./run.sh test` 통과 확인.
- 실제 클라이언트 두 개의 로그인·목록 갱신·로그아웃·재접속·강제 종료·서버 종료 시연.
- 실제 TCP에서 느린 수신자, 동시 접속·종료와 작업 스레드 정리 확인.
- GUI를 추가할 경우 UI 스레드와 화면 갱신 검증.
- 최종 이클립스 프로젝트 제출 형식과 B·C 기능 통합은 별도 작업.
