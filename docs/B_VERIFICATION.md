방 생성·입장·퇴장, 방 전체 채팅 전달, 메시지 번호, 읽음 처리, 연결 종료 시 방 정리가 추가되었다. 서버에서 발신자와 참여 여부를 검사한다. RoomManager 잠금으로 방 상태 변경과 알림 등록 순서를 보호하며, 실제 전송은 연결별 전송 스레드가 수행한다. GUI는 추가되지 않았다.

PR 커밋을 별도 임시 디렉터리에 추출하여 기존 로컬 수정과 분리해 검사했다.

- 승인 후 `java -ea -cp build/classes kr.ac.moyeotalk.RoomTest`: 실제 TCP 방 생성·입장·퇴장, 채팅 번호·공백 보존, 읽음·중복 읽음, 방 밖 사용자 차단, 최근 200개 보관, 강제 연결 종료 정리 통과.

## 남은 문제와 검증 범위

- 방 삭제·메시지 삭제·공지와 C 기능은 미구현이다.
- 방 개수와 메시지별 읽은 사용자 ID 수에는 상한이 없다. 빈 방도 남으므로 장시간 사용 시 자원 관리 보완이 필요하다.
- 최대 길이 채팅 요청은 서버가 메시지 번호를 붙인 응답에서 길이 제한을 초과할 수 있다. 현재 저장 후 전송 단계에서 거부될 수 있어, 응답 길이를 저장 전에 검증하는 보완이 필요하다. 이번 테스트는 이 경계값을 검증하지 않았다.
- 입장·퇴장 시 기존 메시지의 읽지 않은 사용자 수를 다시 알리지는 않는다. 읽음 알림 시점의 현재 참여자 기준으로 계산한다.
- B의 동시 채팅·입퇴장 경합 및 장시간 부하 테스트는 수행하지 않았다. A의 소켓 대역 동시성 검증과 구분한다.
- PowerShell, GUI 및 다른 PC 간 통신은 이번 검증 범위에 포함하지 않았다.
- 개발 공유 ZIP과 최종 제출 ZIP은 갱신하지 않았다. 기존 ZIP을 이번 병합 후 문서까지 일치하는 배포본으로 간주하지 않는다.
