# 텀프로젝트 제출·평가 기준과 필수 점검표

## 근거와 적용 범위

근거: 루트의 `네크워크프로그래밍 텀프로젝트 제출방법 및 평가방법 안내.pdf` 전체 15쪽. 아래 쪽수는 PDF 페이지 순서다.

이 문서는 원본의 필수 요구, 권장 사항, 프로젝트 추가 규칙을 구분한다. 모든 개발·검토·제출 준비에 적용하며, 체크 표시는 실제 자료나 검증 결과가 있을 때만 한다. 문서 작성 자체가 기준 충족을 의미하지 않는다.

## 제출 규칙: PDF 2쪽

- 팀원 모두 이클래스의 **텀프로젝트 최종 결과물 제출** 게시판에 ZIP으로 각자 제출한다.
- 원문 마감은 **16주차가 끝나는 12월 20일 자정까지**다. PDF에 연도와 정확한 시각 표기가 없으므로 해당 학기 이클래스 공지에서 최종 확인한다.
- ZIP에는 최종 보고서, 팀 공통 시연 영상, 제출자 본인의 개인 발표 영상, 최종 소스코드를 포함한다.
- 최종 보고서·공통 영상·소스코드는 팀원 동일 자료를 사용하고, 개인 발표 영상은 팀원별로 다르게 준비한다.
- 최종 소스코드는 **이클립스 프로젝트 폴더 전체**를 압축하여 제출한다. 현재 개발용 소스 ZIP만으로 충족했다고 판단하지 않는다.
- 인터넷 오픈소스를 사용했다면 원본 소스코드와 간단한 원본 실행 영상도 추가한다.
- 주간 보고서는 이미 제출했으므로 별도 재제출은 필요하지 않다.
- 영상은 각각 약 5분이 권장되지만 시간 제한은 없으며 필요한 경우 초과할 수 있다.

소스코드 전체를 보고서에 나열할 필요는 없다. 실제 구현 기능과 주요 메시지를 중심으로 설명한다. 시스템 구성도·흐름도는 선택 사항이다(PDF 4~8쪽).

## 모든 변경에 적용할 품질 규칙

PDF 10~12쪽의 품질 기준에 사용자가 요청한 리소스 효율·과도한 개발 방지 기준을 함께 적용한다. 후자의 두 항목은 PDF에 별도 배점으로 명시된 항목이 아니다.

| 항목 | 필수 점검 |
|---|---|
| 중복 | 동일한 업무 로직의 복제를 줄인다. 몇 줄이 비슷하다는 이유만으로 불필요한 상속·공통화를 만들지 않는다. |
| 예외 | 잘못된 입력, 통신 실패, 초기화 실패를 구분한다. 복구 가능한 입력 오류로 입력 루프 전체가 종료되지 않게 한다. 예상 밖 오류의 원인을 확인할 수 있게 한다. |
| 자원 정리 | 정상·강제 종료, 초기화 실패, 중복 종료, 정리 중 예외에도 소켓과 작업 스레드가 남지 않는지 확인한다. |
| 화면 갱신 | 서버 상태 변경을 클라이언트에 반영한다. GUI 도입 시 UI 스레드 규칙을 지키고 네트워크 대기로 화면을 멈추지 않는다. |
| 충돌 | 중복 로그인, 동시에 변경되는 상태, 메시지 순서와 잠금을 확인한다. 게임의 물리적 충돌 판정은 해당 기능 구현 시 별도 검증한다. |
| 리소스 효율 | 연결 수, 프레임 길이, 대기 시간, 대기열 크기를 관리한다. 느린 사용자 한 명이 전체 처리를 멈추지 않게 한다. |
| 아키텍처 | 통신·명령어 해석·사용자·방·게임 책임을 구분하고 상태를 캡슐화한다. 담당 간 인터페이스를 문서화한다. |
| 과도한 개발 | 현재 요구와 검증 가능한 문제에 필요한 최소 변경을 한다. 기능 수나 추상화 수를 늘리는 것을 난이도·창의성의 증거로 삼지 않는다. |
| 주석 | 한글로 작성하고 이모지는 사용하지 않는다. 초보자가 이해하도록 역할·이유·흐름·검증·정리를 설명한다. 자명한 문법 설명과 시작·끝 표시를 남발하지 않는다. |
| 일관성 | 들여쓰기, 이름, 오류 응답, 통신 형식, 주석과 실제 동작을 일치시킨다. |
| 개인정보 | 테스트와 예제에는 가상 ID·닉네임을 사용한다. 보고서의 신원·기여도는 확인된 값만 넣는다. |

주석의 상세함과 적절함을 함께 지킨다. 이전에 추가한 상세 주석도 정확성·중복 여부를 검토하며, 단순히 주석 수가 많다는 이유로 품질 기준 통과로 보지 않는다.

## 프로토콜 문서 작성 규칙: PDF 4·6쪽

새 메시지를 추가하거나 수정하면 `docs/PROTOCOL.md`에 다음 열을 채운다.

| 기능 | 명령어 | 형식 | 가상 정보로 작성한 예시 | 각 값의 의미 | 전송 방향 | 전송 시점 | 수신 후 처리 |
|---|---|---|---|---|---|---|---|
| 로그인 요청 | `/LOGIN` | `/LOGIN userId nickname` | `/LOGIN user1 테스터1` | 사용자 ID, 표시 닉네임 | 클라이언트 → 서버 | 접속 후 로그인 시 | 인자·중복 검사 후 사용자 등록, 성공 응답 및 전체 목록 알림 |

## 2026-11-22 PR #1 병합 후 추가 검증

위 2026-11-19 체크리스트는 당시 기록이다. 이번에는 승인된 포트 접근으로 A의 실제 TCP 통합 테스트와 B의 RoomTest를 통과했다. B의 방 생성·입장·퇴장, 채팅·읽음은 구현되었으나 방·메시지 삭제와 공지, C 기능은 미구현이다. 실제 TCP 동시 종료 경합 등 미실행 항목을 완료로 간주하지 않는다. 검증 명령과 남은 문제는 [B 병합 검증 기록](B_VERIFICATION.md)을 따른다.
